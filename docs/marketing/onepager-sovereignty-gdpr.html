In place today

What's already enforced

Access control

Four roles, enforced server-side

Super-admin, org-admin, analyst and viewer. Permissions are checked on the API — not just hidden in the UI — so a downgraded or forged client can't reach actions it isn't entitled to.

Credentials

Encrypted auth by default

Passwords are BCrypt-hashed (salted). Sessions are short-lived, signed JSON Web Tokens carrying the user's organisation and role — stateless, with no server-side session store to breach.

Tenancy

Organisation-scoped by design

Every account belongs to an organisation; core records carry an organisation key and the access token is bound to it. The multi-tenant model is the foundation isolation hardening builds on.

Data minimisation

A small personal-data surface

The only personal data held is operator accounts — email, display name, role, last-login. No end-user tracking, no behavioural profiles, no special-category data. Less data is less risk.

Hosting & data residency

You can run it where your rules require

AIIM is fully containerised and configuration-driven, so it deploys onto EU-region cloud or on-premises infrastructure you control. Two points we state openly, because a DPO will ask:

Self-host

Available today. Backend, frontend, database and workers ship as containers with a single compose definition — deployable to an EU-region VM or Kubernetes cluster under your control. No component requires our infrastructure.

Managed EU

On roadmap. A managed EU-region hosting option is planned; until then, EU data residency is achieved via self-host on infrastructure you choose.

Data flows out

Disclosed. Content analysis uses external AI services (large-language-model inference) and some sources are fetched from third-party APIs. Article/message text is sent to those providers for processing. For strict data-residency needs we scope which flows are acceptable and can discuss EU-endpoint or self-hosted-model options.

In transit

Deployments terminate TLS at the edge (reverse proxy / platform). Secrets are supplied via environment configuration, never hard-coded.

Roadmap to full compliance

What we're building next — and why it's honest to name it

These are scoped and prioritised, not shipped. We'd rather a procurement team know exactly where the line is than discover it later.

Compliance roadmap — near term
1

Tenant-isolation hardening

Extend organisation scoping to every remaining query path (global search, background detection jobs) so cross-organisation visibility is impossible by construction, not just by convention.

2

Immutable audit log

A tamper-evident record of create / update / delete and access events — the basis for demonstrating data governance and supporting incident investigation.

3

GDPR data-subject endpoints

Operator-facing export, rectification and erasure (soft-delete preserving the audit trail) to service data-subject requests within statutory timelines.

4

Managed EU-region option

A hosted EU-region deployment for customers who prefer managed service over self-host, with a documented sub-processor list and data-flow map.
